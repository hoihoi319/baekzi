# 「백지」 검증 설계
### 이 도구가 정말 개념적 이해를 높이는가 — 확인 계획 v1

---

## 0. 이 문서가 필요한 이유

「백지」의 소개 탭에는 이렇게 적혀 있다: *"이 화면이 설득력 있다는 것과 실제로 개념적 이해를 높인다는 것은 다른 주장입니다."*
이 문서는 그 두 번째 주장을 **반증 가능한 형태**로 바꾸고, 어떻게 확인할지를 정한다.

핵심은 하나다 — **무엇과 비교할 것인가.**

---

## 1. 무엇을 검증하는가

「백지」는 세 가지를 주장한다. 검증 가능한 것과 아닌 것을 먼저 갈라 둔다.

| # | 주장 | 검증 가능성 |
|---|---|---|
| 1 | 절차만 아는 상태를 **드러낸다** (계산 100% / 의미 0%) | **이미 참** — 엔진이 결정론적이라 구조적으로 보장됨. 실험 불필요 |
| 2 | 가르치는 활동이 **개념적 이해를 높인다** | 검증 필요 — 다만 이건 protégé effect의 재확인이지 이 도구의 고유 기여가 아님 |
| 3 | **실패가 되돌아오는 것**이 그냥 설명을 쓰는 것보다 낫다 | **← 이것이 이 프로젝트의 고유 주장.** 여기에 설계를 집중한다 |

> 3번을 재려면 대조군이 "아무것도 안 함"이어서는 안 된다. **설명은 쓰되 실행되지 않는 조건**이 있어야 한다.

---

## 2. 조건 — 대조군 설계가 전부다

같은 차시, 같은 개념, 같은 시간. **활동만 다르게 한다.**

| 조건 | 활동 | 통제하는 것 |
|---|---|---|
| **C. 연습** | 같은 개념의 문제를 풀고 교사 해설을 듣는다 | 학습 시간의 기저선 |
| **A. 설명 쓰기** | 「백지」와 **같은 6개 항목**을 종이에 자기 말로 설명한다. 채점·피드백 없음 | 자기설명 효과 (제자 없이) |
| **B. 백지** | 설명이 제자에게 실행되고, 시험 결과와 회귀가 되돌아온다 | A + **실행 피드백 루프** |

**핵심 비교는 B vs A다.** C는 활동이 아예 없을 때의 기저선일 뿐이다.
B > A 가 나오지 않으면 — 이 도구가 하는 일은 "설명 쓰기 워크시트"로 충분하다는 뜻이고, 그건 정직하게 보고해야 할 결과다.

**A 조건 설계 시 주의**: A에게도 「백지」와 동일한 **6개 항목 목록**을 준다. 목록 자체(무엇을 설명해야 하는지 알려주는 것)가 강력한 개입이므로, 그것까지 B의 공으로 돌리면 안 된다.

---

## 3. 가설

- **H1 (핵심)** B의 **지연 검사 개념 문항** 성취 > A. *(사전 성취 통제)*
- **H2** A > C. 자기설명 효과 자체는 재확인된다.
- **H3** 세 조건의 **절차 문항** 성취는 차이가 없거나 작다. → 이 도구는 계산을 잘하게 만드는 도구가 **아니다**.
- **H4 (매개)** B의 효과는 **슬롯 커버리지**(특히 의미·설명 슬롯 충족)가 매개한다.
- **H5 (탐색)** B 안에서 **회귀를 겪은 학생**이 겪지 않은 학생보다 오개념 재발이 적다.
  → 무작위 배정이 아니므로 **인과 주장 불가.** 탐색적 분석으로 명시한다.

---

## 4. 준거 변수 — 앱 문항을 그대로 쓰면 안 된다

앱의 10문항으로 사후 검사를 하면 **연습 효과**를 재는 것이 된다.
별도 문항 은행을 만들되, **구조는 같고 표면만 다르게** 한다.

| 층위 | 문항 예 (분수 나눗셈) | 배점 |
|---|---|---|
| **절차** | 계산 6문항 (수치만 바꿈) | 0/1 |
| **의미** | "8 ÷ ¼ = 32인데 나눗셈인데 왜 커졌나?" (앱은 6 ÷ ½ 사용) | 0–2 루브릭 |
| **전이** | 처음 보는 맥락 — "리본 3 m로 ⅖ m짜리 매듭을 몇 개?" | 0–2 |
| **오개념 지속** | "¾ ÷ ⅕ 의 답은 ¾보다 큰가 작은가?" (계산 없이 방향만) | 0/1 |
| **설명 생성** | "왜 뒤집어 곱하는지 후배에게 설명해 보라" | 0–3 루브릭 |

**채점**: 루브릭 문항은 **조건을 가린 채(blind)** 두 명이 독립 채점하고, 일치도(Cohen's κ)를 함께 보고한다. κ < .7이면 루브릭을 고쳐 재채점한다.

**측정 시점**

```
사전검사 ─── 4주 처치(주 1회 40분) ─── 즉시 사후 ─── 3주 후 지연검사
```

**주 준거는 지연검사다.** 개념적 이해와 절차적 암기는 즉시 사후에서는 잘 갈리지 않고, 시간이 지나야 갈린다.

## 5. 앱이 내보내야 하는 프로세스 로그

H4(매개)를 보려면 앱 내부 지표가 필요하다. 현재 앱은 로그를 밖으로 내보내지 못한다 — **구현 과제 1순위.**

```json
{
  "student": "익명 ID", "concept": "fracdiv", "session": 3,
  "versions": [
    { "v": 1, "taughtText": "…", "slotsAdded": ["procedure","reciprocal"],
      "partial": {}, "pass": ["C2"], "broke": [], "mode": "rule|ai" }
  ],
  "final": { "calc": [5,5], "meaning": [3,3], "explain": [2,2] },
  "regressionExperienced": true,
  "teachCount": 7, "elapsedSec": 1840
}
```

**분석에 쓰는 파생 지표**
- `슬롯 커버리지` — 의미·설명 슬롯 충족 여부 (H4 매개변수)
- `회귀 경험` — 0/1 (H5)
- `가르친 문장 수`, `평균 문장 길이` — 참여도 통제 변수
- `부분 이해 발생 횟수` — AI 모드에서만

## 6. 분석 계획 (사전등록 대상)

- 주 분석: **사전 성취를 공변량으로 하는 ANCOVA.** 학급 단위 배정이면 **학급 랜덤절편 다층모형**으로 군집 보정.
- 계획된 대비: **B vs A** (핵심), A vs C.
- 효과크기 Hedges' *g* 와 95% 신뢰구간을 반드시 함께 보고.
- H4는 매개분석(간접효과 부트스트랩 5,000회).
- **데이터 수집 전 OSF에 분석 계획을 등록한다.** 결과를 보고 가설을 고치는 일을 막기 위해서다.

**표본 크기**

| 비교 | 가정 | 필요 표본 |
|---|---|---|
| B vs A (2군) | d = 0.4, α = .05, power = .80 | 군당 약 **100명** |
| 3군 전체 | f = 0.20 | 총 약 **250명** |
| 군집 보정 | ICC ≈ .10, 학급 25명 → 설계효과 ≈ 3.4 | 위 수치의 **3.4배** |

→ **개인 프로젝트로는 본 연구를 감당할 수 없다.** 그래서 아래처럼 쪼갠다.

## 7. 현실적인 단계 — 지금 할 수 있는 것부터

| 단계 | 규모 | 목표 | 산출물 | 소요 |
|---|---|---|---|---|
| **0. 사용성 관찰** | 학생 **5명**, 1인 30분 | 효과 아님. **말이 통하는지**를 본다 | 관찰 노트 + 수정 목록 | 1주 |
| **1. 단일군 파일럿** | 1개 학급 (25명), 2차시 | 실행 가능성 · 로그 수집 · 소요 시간 · 이탈률 | 파일럿 보고서 | 2주 |
| **2. 소규모 비교** | 2개 학급, **A vs B** | 효과크기 **추정**(검정 아님) | 효과크기 + 신뢰구간 | 6주 |
| **3. 본 연구** | 다기관, 3조건 | 가설 검정 | 사전등록 + 논문 | 별도 |

**0단계를 반드시 먼저 한다.** 지금 앱의 모든 문구는 내 가정이다. 5명만 관찰해도 그중 절반은 틀렸다는 게 드러난다.

**0단계 관찰 프로토콜 (30분)**
1. 아무 설명 없이 태블릿을 건네고 **말하면서 하게** 한다 (think-aloud).
2. 개입 없이 관찰. 도움을 요청하면 "어떻게 하면 될 것 같아?"로만 되묻는다.
3. 기록할 다섯 가지:
   - **"제자를 가르친다"는 구도**를 몇 초 만에 이해하는가
   - 슬롯 6개 목록을 보고 **압도당하는가**
   - 첫 시험 결과에서 **계산 100% / 의미 0%를 스스로 읽어내는가**
   - **회귀**가 났을 때 — 통찰인가, 좌절인가 (표정·발화 그대로 기록)
   - 어느 문장에서 **손이 멈추는가**
4. 끝나고 세 가지만 묻는다: 제자가 왜 틀렸다고 생각해? / 제일 답답했던 순간은? / 친구에게 뭐라고 설명할래?

## 8. 위협 요인과 대응

| 위협 | 대응 |
|---|---|
| **신기성 효과** — 새 도구라서 재밌었을 뿐 | 처치 4주 이상 + **지연검사**를 주 준거로 |
| **교사 효과** — 조건별 교사가 다르면 교사를 재는 것 | 같은 교사가 두 조건 모두 담당하거나 교사 교차 배정 |
| **채점자 편향** | 조건 블라인드 + 이중 채점 + κ 보고 |
| **회귀가 좌절이 될 위험** | 정서 반응 3문항(재미·좌절·자신감)을 매 차시 측정. 이탈률·중도포기 기록 |
| **굿하트의 법칙** | 커버리지를 **성적으로 제시하지 않는다.** 학생 모드에 점수·석차 표기 금지 |
| **AI 추출기의 관대함** | 조건 B는 **동일 모델·동일 설정** 고정. 학생 문장 100개를 교사 5명 채점과 대조해 κ 보고 |
| **호손 효과** | 관찰자는 교실 뒤에 고정, 개입 없음. 사전에 학생에게 "도구를 평가하는 것이지 너를 평가하는 게 아니다"라고 고지 |

## 9. 윤리

- 학생 로그는 **익명 ID**로만 저장하고, 자유 입력 텍스트는 슬롯 태그로 변환 후 원문 파기 옵션을 둔다.
- **평가·서열화 금지**를 문서로 명시하고, 교사에게도 같은 조건을 안내한다.
- 학생·보호자 사전 고지와 동의. **미참여 학생을 위한 동등한 비-AI 경로**를 반드시 마련한다.
- AI 모드에서 학생 문장이 외부로 나가는 경우, 무료 등급의 데이터 사용 정책을 사전에 확인한다.
  → **로컬 모델을 기본으로 권장**하는 이유가 여기 있다.

## 10. 결과가 어떻게 나오든 보고할 것

- **B > A** — 실행 피드백 루프에 고유 기여가 있다. 이 프로젝트의 핵심 주장이 지지된다.
- **B ≈ A** — 이 도구가 하는 일은 **잘 만든 설명 쓰기 워크시트**로 충분하다.
  그렇다면 도구의 가치는 학습 효과가 아니라 **교사가 학급의 빈 슬롯을 한눈에 보는 것**으로 재정의해야 한다.
- **B < A** — 화면과 게임적 요소가 오히려 주의를 뺏었을 가능성. UI를 덜어내는 방향으로 되돌린다.

세 결과 모두 이 문서에 미리 적어 둔다. **어떤 결과가 나와야 하는지 정해 놓고 시작하지 않기 위해서다.**
